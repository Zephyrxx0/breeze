<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public Internet → AWS Amplify Hosting CDN | User traffic requesting static SPA assets and deep links |
| Amplify SPA → AWS Lambda Function URL | Browser AJAX requests for `/api/assess` across domains |
| Build Environment → Production Assets | Injection of `VITE_API_BASE_URL` into production JavaScript bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Spoofing / CSRF | Lambda Function URL CORS | mitigate | In Task 3, update `AllowedOrigin` on the Function URL from wildcard `*` to the exact deployed Amplify domain `https://main.<app-id>.amplifyapp.com`, preventing unauthorized web origins from querying the API. |
| T-03-05 | Information Disclosure | Client JS Bundle | mitigate | `VITE_API_BASE_URL` is an unauthenticated public endpoint. Zero secret keys are prefixed with `VITE_` or embedded into client bundles. `OPENAQ_API_KEY` remains strictly in Lambda env. |
| T-03-06 | Denial of Service / Routing Failure | Amplify SPA Routing | mitigate | Task 1 and Task 2 apply the exact regex SPA rewrite rule: non-asset paths rewrite to `/index.html` with HTTP 200, preventing 404 broken deep links while static JS/CSS assets bypass the rewrite. |
</threat_model>
