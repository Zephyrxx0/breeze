## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| smoke script → live upstreams (via spawned API) | Real keys and real rate limits — a buggy script can burn OpenAQ quota or hang the demo laptop |
| browser → local API via Vite proxy | The skeleton renders server JSON directly as user-visible strings |
| .env → spawned processes | The OpenAQ key is inherited by every child process the smoke script spawns |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-16 | Denial of Service | smoke rate limits | mitigate | 4 places × (1 bbox + ≤3 latest) per run plus 1 blackhole check — orders of magnitude under OpenAQ's 60 req/min; no retry loops; children always SIGKILLed in `finally` so no orphaned servers hold ports |
| T-01-17 | Information Disclosure | smoke output & logs | mitigate | Smoke prints statuses, sources and mixes only — never env values or the key; assertions reference `sources.openaq.status`, never a key-derived field (Pitfall 6) |
| T-01-18 | Tampering | debug renderer string handling | mitigate | The browser renders core-emitted strings verbatim with `textContent` via React — no innerHTML; the failure branch is hard-gated by tests/grep to contain no verdict word |
| T-01-19 | Repudiation | phase exit | accept | The human checkpoint is the audit point: the user personally observes verdict honesty, fail-soft behavior and the smoke pass before Phase 1 closes |
| T-01-SC | Tampering | npm installs | mitigate | No new dependencies (tsx, vite already gated in 01-01); smoke uses only live upstreams — no fixture or mock module exists in scripts/ or apps/ |
